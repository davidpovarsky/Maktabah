- Direct download and working-directory cleanup entries now use the same gate. Download cancellation or changed authorization after HTTP disposes only its own URLSession temporary file before publishing a staged file.
- The downstream checkpoint helper consumes/closes its connection, checks actual SQLite return codes for archive and FTS, and delegates WAL/SHM lifetime entirely to SQLite. All nine manual sidecar deletions in the updater import/rename/rollback/checkpoint path are removed. A checkpoint failure now throws before IntegrationCache/notification publication at that call site. Connection ownership is cleared before the consuming call to prevent double close if it throws. Busy-reader, FTS-after-archive checkpoint failure, successful reopen, and uncommitted-write rollback are exercised on disposable databases. This preserves recoverability; it does not undo independently committed archive/FTS/author/main writes.

Invalid quote placement, partial author batches, negative/overflow values, unexpected columns, duplicate IDs, injected Google Drive query fragments, NULs and excessive input/row counts reject the whole catalog before staging. No last-author-wins recovery is inferred from malformed input.
