## Concrete source gaps, without broadening authority

These are bounded remaining capabilities, not permission to silently weaken existing guards. `SOURCE_GAPS.json` binds the source locations, original requirement IDs, existing tests and ownership proposal for each.

1. **Saved Results list/folder/record navigation.** The real Search toolbar opens `SearchModeView.showingSavedResults`; its sheet constructs `iOSSavedResultsView`. That view uses the original `ResultsViewModel`, `FolderNode` navigation and result loading, but the current finite native registry/services have no retained Saved Results parent/folder/record route. History/Favorites card routing does not implement these nine inventory rows. Start with reveal-only list/folder/record navigation; save, move, rename and delete remain separate original user-confirmed operations.
2. **Remembered-position History open.** The new typed service deliberately reveals an exact original History/Favorite card. It does not consume the history entry's original saved locator through `reader.open`. The original inventory separately names `inventory.v1.history.open-entry` with exact remembered position. Preserve that distinction from both card reveal and old numeric widget links.
3. **Profile/Group selection from another global page, and unqualified legacy cold tabs.** `MaktabahNativeWorkspaceSelectionBinding.validate` requires actual selectedTab/currentMode `.viewer` with unchanged root/mode/Settings publications. Native staging rejects empty legacy tabs whose old load path issues an unretained token later. These are truthful current limitations. The newly delivered Viewer continuation and hidden-phone presentation repair apply to ReaderTab; they do not automatically authorize Profile/Group Store publication.
4. **Production/public Search hit and paging entry.** `ShowSearchResultsIntent` exposes query/books/exact-phrase/sort/window. The service explicitly rejects any supplied selectedHit/cursor; the original results query accepts only the common exact-phrase/distance-zero/default-first-page subset, and nonempty native scope is Otzaria-only. A real loaded-hit/one-page continuation now exists internally, and the new native DEBUG probe exercises it. That does not yet expose the required production semantic entry. The UI agent owns the next narrow proposal.
5. **Independent commentary/draft intent variants and exact Inspector selection.** The original `NativeReaderIntentService.open` accepts either no commentary/note pair, or both commentaryWorkIdentifier and proposedText; one alone is refused. The combined commentary→unsaved draft journey and Core commentary/draft actions remain valid delivered slices. They are not an independent commentary-only system action, a selected saved annotation, or an exact Inspector tool/commentary-group/note-item route. `native.reader.inspector` currently registers the parent only.
6. **Notes/Annotations selected records and editor controls.** The annotations root and original unsaved note draft are implemented. The current registry has no finite annotation-ID, list filter, original note body/tag/style focus or book-specific annotation-row selection contract. Opening the parent or a draft at the Reader source does not close all these original meaningful control rows. No GET save/import/delete/export effect is implied.
7. **Remaining fine controls.** Library currently advertises contents/grouping/downloaded-filter/options; TOC has finite contents/structure/current-selected-row controls. The broader original category/book-info/selected-work, arbitrary TOC node/query/expansion, Reader in-book search/view-options/slider/text-range and Authors/Narrators selection rows are not all supplied by these finite anchors. Each needs a specific retained original-owner design or an explicit unsuitable/unavailable classification; do not copy a view or accept arbitrary paths to fill the inventory.
8. **RN component coverage beyond the root.** The real original React surface now has a bridge/epoch/ready owner and an independent UIKit witness; this fixes the previously absent visible-host construction. It is a parent-only contract. The 45 original RN source rows are not 45 native component journeys. Meaningful inner targets still need finite original component contracts; account/destructive/private rows are not automatically public actions. No headless echo is accepted as visible RN proof.

The original page-aware Sidebar toggle/icon criterion and the exact screenshot/top-chrome requirements remain explicit visual acceptance items. This audit does not invent a second toolbar button, assume an OS-owned icon meets the criterion, or mark source-visible animation as physical proof.
