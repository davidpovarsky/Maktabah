## מה הוחלט

- **הממשק הגלוי נשאר SwiftUI/UIKit של Maktabah/ChavrusaText**, לא Flutter/React Native של אוצריא. מנוע Sefaria המקורי יכול להישאר Hermes headless *לנתונים*; לא לארח את מסכיו הגלויים ב־UI הרגיל.
- **לא בונים BackendCoordinator חדש**: נשמרים `Source/LibraryBackend/*`, המיקומים/היסטוריה, מטא־דאטה, החיפוש המשותף, מתאמי Sefaria הקיימים וה־Reader המקורי.
- **מנוע החיפוש של אוצריא כבר משולב ב־Rust**. נדרשת *העלאה מבוקרת של pin*, עדכון גשר C/Swift, והתאמת אינדקס, לא החלפה של האלגוריתם ב־Swift.
- **טבלאות ספריית אוצריא נקראות ב־Swift+SQLite**, תוך שחזור התנהגות מאומתת מתיעוד הסכמה, בלי להטמיע Flutter או Kotlin JVM בתוך iOS.
- כל התכונות החדשות מתקיימות בתוך namespace downstream; הקוד המקורי של Maktabah הוא `READ-ONLY` לפי מדיניות הפרויקט. אפילו hook זעיר בקוד upstream מחייב **אישור בעלים מדויק לקובץ ול־hunk**, ולא אישור כללי לתוכנית.
- **רישום קובצי Swift חדשים ב־Xcode אינו אוטומטי:** `Maktabah.xcodeproj/project.pbxproj` מכיל `PBXBuildFile`/`PBXFileReference` מפורשים עבור קוד היישום, וה־folder-synchronized group שזוהה הוא עבור UI tests בלבד. רישום קובצי Swift חדשים ב־Compile Sources דורש הצעת שינוי מדויקת ואישור owner להגנה על קובץ הפרויקט; עד אז הם אינם "integrated".
- אין מיזוג ל־`dev`/`main`, אין עבודה על הענף המקורי, אין העלאה ל־TestFlight או הפעלת GitHub Actions ללא בקשה מפורשת מתאימה. אין כתיבה ל־Asana ללא בקשה מפורשת לסנכרון/עדכון.

## ממצאים שמחייבים תשומת לב מיוחדת

- **פער סכמה במנוע**: pin נוכחי `265a14e...` / schema 4, מנוע רשמי 7.0.1 `225a6d5...` / schema 10 — אינדקסים קודמים אינם תואמים, יש צורך לבנות ולפרסם אינדקס תואם מחדש לפני הפעלה מלאה.
- **מסד רשמי אחרון שנצפה**: release `v36-20261101064231`, `seforim-schema7.db.zst`, לא השם ההיסטורי הקבוע `seforim.db.zst`. נדרש לזהות לפי גרסה ו־SHA.
- **גשר Sefaria**: יש שני backends פעילים (`sefaria`, `sefariaEmbedded`); שינוי אוצריא אינו רשאי למחוק/לשכתב אותם. קיים חשד נקודתי לבדיקת backend שגויה ב־Inspector.
- **מיקומי שורות**: fallback ב־`OtzariaGenericBackendAdapter` יוצר מזהי שורה `content.id + offset`; יש להפסיק להציגם כמיקומים קנוניים.
- **גרסאות טקסט**: `version_line` שאינה קיימת עבור שורה = השורה **אינה קיימת באותה מהדורה**; אסור ליפול לטקסט הממוזג ולהציג כאילו מדובר במהדורה שנבחרה.
- **זכויות שימוש**: מנוע Rust ברישיון MIT, אך קוד Flutter של אוצריא ומעדכן Dart תחת Personal Use License, ו־SeforimLibrary תחת AGPLv3 עם ייחוס נוסף. אין להעתיק רכיבים מוגנים למוצר המופץ ללא בירור/היתר.

## תנאי הסיום

התוצאה הרצויה היא **PR/ענף עבודה downstream מוגדר ומתועד** עם יכולות SQLite שימושיות, Rust pin תואם, אינדקס תואם, בדיקות שהורצו בפועל, ותנאי חסימה מפורשים לכל חסר; לא הצהרת "מושלם" על סמך קומפילציה בלבד. כל שער requiring iPad/בעלים/רישיון נשאר פתוח עד קבלת ראיות.

## הבדל בין מצבי הידע

- **Verified from source**: סכמת SQLite וקובצי API מדויקים, הגדרות Adapter/BackendCoordinator, שמות רכיבי Rust, חבילות ומהדורות, כללי ריפו.
- **Code-level risk**: מיקומים מומצאים, התאמת תוצאה לעמוד בעת pagination, התנגשות בחוזי מהדורות, פוטנציאל state של Inspector.
- **Not verified on hardware**: מהירות iPad בפועל, הפעלה מקצה־לקצה ב־v36, החיפוש החדש מול corpus מלא, שימוש RN visibly, זמינות הרשאות הפצה.

**חשוב:** אין דרך להכין מראש את כל ההתאמות הבינאריות וה־ABI של `rust/src/api/search_engine.rs` בלי לקמפל בפועל, אבל החבילה מגדירה בדיוק את קובץ המקור, הממשק הרצוי, ה־fail-closed והתוצרים שמותר לסוכן לבצע *בלי מחקר פתוח או שינוי ארכיטקטורה על דעת עצמו*.
