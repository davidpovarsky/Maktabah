2. Changed actual source, changed full version at same revision, changed revision, unsupported body/envelope and pending deletion each refuse preparation/mark before a possible marker.
3. Ambient outer transaction: prepare, mark and abandonment refuse before writes; SAVEPOINT release cannot be returned as durable proof.
4. First marker commits exactly once. Repeat mark refuses. Retire/error/reopen/new session/new revision/different account/different Space cannot produce another active attempt for that saved UUID.
5. Explicit abandonment of a genuinely prepared record preserves it as history. Old handle cannot mark afterward. A new current session prepares a new UUID without adopting the prior caller.
6. Competing mark versus explicit abandonment is serialized: exactly one state transition wins; abandonment cannot clear a winning possible marker. Two competing preparations cannot gain two active saved-row slots.
7. Cancellation/retirement before commit rolls back or refuses; after a real commit the exact durable record is returned, labeled without ownership when needed. No normal annotation didCommit/CloudKit callback is invoked by a state-only write.
8. Read-only history of absent schema creates nothing; unknown/partial/tampered schema, triggers and UUID case ambiguity fail closed. Frozen payload/source or canonical base64 corruption cannot be treated as a fresh attempt.
9. Exact before/after original annotation, saved-version history, sync_pending, outbox and native identity rows remain unchanged by attempt bookkeeping; only owned attempt schema/rows are affected.
