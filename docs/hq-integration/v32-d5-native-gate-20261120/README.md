# Full v32 d5 native occurrence evidence gate

This extends the existing full-v32 native acceptance wrapper to validate the new engine on the original published corpus after native installation and after an actual cold process restart. The original download resume, three search modes, golden IDs/order/references/highlight count, no reindex, no repeat download, distinct PIDs, and source/installed database SHA256 gates remain unchanged.

The added gate requires two actual Swift/C exact-token results in each process. It authenticates the independent 7,080,797-row / 7,876-book SQL oracle from the retained raw gzip bytes (SHA256 015b4ac382b8c6005d672234cfa7fc1ddaf291f7e5e0d07982f2c89db242f781), and the qualification review at its immutable Git-LF SHA256 3ccd704a831f4a96ec06a691bdc17e7a8988168659bad766815018c9106983a1. Windows CRLF checkouts are normalized only for this explicitly named Git-LF hash. The original Windows report remains separately preserved under its original raw hash in the qualification package.

Required independent SQL totals are 143,982 distinct token positions in 104,120 matching documents for בראשית, and 170,515 positions in 109,419 documents for אברהם. Matching-document counts never substitute for occurrence counts. Each phase must also retain the original 265 artifact producer, actual d5 consumer/resource identity, exact global request and published hard limits, original full index segment without deletes, full live document coverage, and original decoded proof/work fields. Request tokens and generation identifiers are validated within their process; they are not forced equal across restart.

Actual verification: 26 Python test methods passed, including all 15 original method ASTs unchanged. The first 26-method run preceded a small review follow-up; the final run also rejects numeric-equivalent float values for integer request/source fields. These are synthetic evidence-gate controls, not native execution or an engine rerun. The retained Windows C responses are used only as controlled schema examples in the tests. Independent source review found no blocker; its integer-type suggestion was implemented and checked.

The only executable files changed by this branch are downstream CI Python files. No app, original engine, source database, index, downloader, installer, SDK or user data was modified. The Swift acceptance-only probe is a separate reviewed change. This branch still retains the old APP_SOURCE constant until the combined app source is sealed. It must not be dispatched before that source pin and the shared build inputs are updated and the complete preflight passes.

Native executed for this gate change: 0. Apple SDK/typecheck: NOT_RUN. Full-v32 d5 runtime and UI/physical-device acceptance are separate gates. The direct Swift/C probe does not establish Core permission admission or UI behavior.
