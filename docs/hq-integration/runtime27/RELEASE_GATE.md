# Mandatory pre-signing UI gate

The existing manual ios-testflight workflow now requires ui_acceptance_run and executes verify-runtime27-release-gate.py immediately after checkout, before dependency work or certificate import/signing. There is no skip input; no shipping workflow was dispatched to test it. Existing trigger scope and other input defaults are preserved.

It rejects missing/failed/stale runs, a different exact checkout, a different workflow/event, expired/missing/duplicate artifacts or missing ZIP digest, unsafe extraction, partial/build-only/probe evidence, a different full release manifest, missing device/data configurations, mismatched OS/device/binary/input provenance and failed/skipped/zero/missing named UI cases. The downloaded artifact's raw summary, test tree and log are reverified with the same strengthened guard; a self-reported PASS count is insufficient. Real native data installation evidence must have an explicit matching expected digest and quick_check, with full-corpus size/book counts for the production Release configuration.

A documentation-only descendant can preserve the tested pass with a bounded Git proof: tested ancestry, all changed paths confined to docs/hq-integration, and a retained exact diff SHA256. Every app/test/data/dependency/tool/configuration byte stays unchanged. The gate records both tested and candidate SHAs, rechecks the raw results and retains the24-hour freshness bound; all other source changes require affected-case validation. This avoids rebuilding healthy UI suites merely to add their evidence report.
