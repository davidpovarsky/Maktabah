# Ordinary Settings success receipt, schema v1

This is the sole producer contract shared by the study UI controller and the R08 search consumer. The schema describes an **actual completed original Settings v40 to v41 update**. No positive production envelope has been generated by this source checkpoint. The helper and its controls do not launch Maktabah, run XCTest, download a database, change user data or supply search results.

## Entry points

The controller imports `Scripts/CI/study-ui-settings-receipts.py` with `importlib.util` or `runpy`. All paths below are absolute, canonical paths. Evidence outputs must be fresh files under the same checkout's `build/artifacts`; existing files are never overwritten.

```python
require_production_profile(manifest)

owner = discover_owner(simulator_udid, container_parent)
# container_parent is the observed same-UDID Containers/Data/Application path.

before_file = capture_before(
    owner=owner,
    actual_installation_receipt=output / "actual-full-v40-installation.json",
    output=output / "settings-before.json",
)

sealed_file = seal_success(
    before_receipt=before_file["path"],
    before_sha256=before_file["sha256"],
    owner_after=observed_owner_after,
    context_binding=context_binding,
    case_directory=actual_settings_case_directory,
    original_installation_result=original_v40_installer_result,
    checkout_sha=actual_current_checkout_sha,
    official_metadata_paths={
        "release": observed_raw_release_json,
        "fullManifest": observed_raw_full_manifest_json,
        "statistics": observed_raw_statistics_json,
    },
    trace_baseline=qualified_original_pages_trace,
    output=output / "settings-update-success.json",
)
```

`capture_before` reuses the database witness from the root controller's just-completed, full-hash/full-count `RetainedV40Installation.admit_current_installation` result. It verifies the actual MCM owner, database size, raw installed manifest and both installed package identities/inventories. It does not repeat that 4 GB hash. The registered Settings UI case independently hashes the original database before any update and during rollback/recovery. The envelope also retains the immutable prior admission file.

`seal_success` independently streams the **final database** once and checks its exact hash against the actual Settings attachment, then opens SQLite with `mode=ro&immutable=1`, enables `query_only`, runs `quick_check` and counts all `book`, `line` and `link` rows. The complete file's device/inode/size/mtime/ctime must be unchanged through that observation. No replacement database is created.

The caller must complete its existing same-checkout app/SDK image admission and post-execution image verification, and retain/shutdown the owned simulator as already required by the root controller. This helper verifies the current committed helper/registered-test/verifier files, current checkout, admitted current build receipt and original installation receipt. It does not substitute its source check for the controller's actual installed Mach-O/SDK/runtime verification. Publish the envelope only after those controller checks succeed.

## Shared wire types

`FileWitness` is exactly `{path, bytes, sha256}`. `RawManifestWitness` is exactly `{sourcePath, rawBase64, bytes, sha256}`; the raw bytes are the complete original file, not JSON reserialization. All byte lengths, inode values, `mtimeNs` and `ctimeNs` are JSON integers within signed Int64; they are never floating-point timestamps.

| Field | Required meaning |
| --- | --- |
| `schemaVersion`, `status` | `1`, `ORIGINAL_SETTINGS_UPDATE_VERIFIED` |
| `simulatorUDID`, `bundleID`, `checkoutSHA` | Actual canonical owned UDID, `com.davidpovarsky.chavrusatext`, exact current Git SHA |
| `dataContainerBefore`, `dataContainerAfter` | Actual MCM-discovered application containers; storage may instead use the actual App Group |
| `originalInstallationResult` | Immutable FileWitness for the real successful retained-v40 installer `RESULT.json`; its created UDID and admitted prior receipt must agree |
| `settingsExecution` | Actual full selector, `caseStatus: "Passed"`, `executedTests: 1`, `skippedTests: 0`, FileWitnesses for case result, zero-skip result, installed and official-target attachments, and actual `xcresultPath` |
| `context` | Immutable original `input` FileWitness, separately observed `effective` FileWitness and a bounded chain of actual MCM owner relocations |
| `before`, `after` | Database FileWitness, raw installation manifest and exactly two index snapshots |
| `officialTarget` | Verified published release ID/tag/repository, manifest/statistics asset IDs/names/bytes/digests, exact published statistics and raw metadata FileWitnesses |
| `cleanup` | Actual absence of all defined transaction, download and staging artifacts |
| `traceBaseline` | Existing qualified prior pages trace, linked to its actual passing case and original pages/independent-SQL attachment |

Additional producer fields retain the pre-update receipt, original database admission, actual MCM owner bytes, final SQL/file identity, actual source/build provenance and before/after user-state attachments. The R08 consumer reads a Codable subset. `POST_UPDATE_RECEIPT.schema.json` describes the common fields; semantic cross-file bindings are enforced by the helper.

All `caseID` values are the **full** `target/class/method` only-testing selector. `caseStatus` is the literal `Passed`; `caseResult` is a FileWitness, not a status string. The Settings selector is:

```
Maktabah-iOSUITests/ManagedLibraryUpdateAcceptanceTests/testOrdinarySettingsUpdatePreservesProductionLibraryAndUserState
```

## Actual xcresult binding

Each original case must have its own controller directory containing `RESULT.json`, `original-ui.log`, `original.xcresult`, `zero-skip.json`, `zero-skip.summary.json`, `zero-skip.tests.json` and exported `captures/manifest.json`. The root's `run_original_case` already produces this layout.

The helper reuses the exact original `tools/verify_xcresult_zero_skips.py` **file-based** verification function against the retained raw summary/tree/log. It does not invoke `xcrun` or XCTest. The command must identify the same one full selector, same UDID and same xcresult directory. Both raw xcresult exports must match the verifier's stored digests. Exactly one explicit passing UI test, zero failures and zero skips are required.

Attachments are selected from the actual xcresult export manifest, scoped to the exact selected test and actual device ID. The helper requires exactly one original `settings-update-installed` and `settings-update-official-target` JSON attachment. Exported UUID filenames must stay inside the captures directory without symbolic links. A same-named JSON file from another case, wrong device, duplicate or escaped path is rejected. Before/after `settings-update-user-state-*` attachments must also be present and equal as JSON objects.

## Existing trace baseline

The root owns selection of one actual prior passed v40 page case. Allowed full selectors are the Otzaria cumulative-metadata pages case or the Zayit 50/100/150 pages case in `PublishedProductionSearchDataTests`. Its `sourceAttachment` must be the actual exported `published-v40-<engine>-original-pages-and-independent-sql` attachment containing `events` and a nonempty `independentSQL` object.

`traceBaseline` contains `namespace`, `relativePath`, `bytes`, `sha256`, numeric Int64 `inode`, `mtimeNs`, `ctimeNs`, actual `processID`, full `caseID`, `caseStatus: "Passed"`, `caseResult`, `xcresultPath`, `sourceAttachment` and `sourceDatabaseManifestSHA256`. The last digest equals `before.installationManifest.sha256`. The relative path is exactly `Documents/OtzariaLogs/search-native-<namespace>.jsonl` in the current real application container.

The trace must already exist, end with a newline and contain original provider **and** published events. Every event must identify the same actual namespace/process/production profile/engine; its complete event array must equal the original page-case attachment. Missing/empty files never count as a successful negative search observation. R08 reuses this existing namespace with the original trace launch arguments and separately requires the unchanged prior prefix. Root's active app logs/PIDs remain necessary to bind both new v41 submissions; the helper does not infer active search execution from silence.

## Read-only container relocation

`discover_owner` scans only the supplied same-UDID application/App Group parents, bounded to 256 children each. It requires the sole actual application metadata identifier and at most one actual App Group identifier, retains raw original MCM metadata bytes and chooses normal storage ownership. It never searches arbitrary databases or treats a matching filename as proof of ownership.

`context_binding` has `{input, effective, relocations}`. Both file witnesses stay immutable. Each relocation is `{before: OwnerRecord, after: OwnerRecord}`, with full `discover_owner` observations; the chain may begin at an input-context owner that predates the pre-update snapshot, must contain the actual snapshot owner and must end at `owner_after`. Every historical owner has exact raw MCM bytes/digest and bound original app/group paths on the same device. Database/download/workspace/qualified-store paths must match those actual owners; the annotation store's logical relative path must stay the same. Non-path context fields cannot change. The helper validates this chain but does not manufacture or rewrite an effective context file.

The test runner must still receive a context valid **when XCTest uses it**. If XCTest relocates the application after the host prepared the context, a test-side read-only owner admission or a new actual observed effective context is required. This helper deliberately rejects an unexplained path substitution and cannot turn a test that used stale absolute paths into a passing test.
