## Implemented behavior

1. Line-mode first/exact/next/previous descriptors now select one metadata row
   with actual previous/next indices using indexed SQLite queries. They no
   longer build or retain all line summaries for a book. Sparse holes stay
   holes; content decoding remains separate. Paragraph/chapter grouping and
   complete-unit assembly remain the existing implementation.
2. `lineAnchorAsync` validates the database generation captured when the
   request started as well as the worker's lease. A replacement before the
   worker acquires its connection now cancels the old request instead of
   returning an anchor from the replacement database.
3. The generic reader section adapter uses existing throwing service access
   rather than error-erasing optional wrappers. SQL/decode failures propagate
   instead of returning a misleading single-row fallback; adjacent metadata
   errors cannot silently advertise the end of the book. A genuinely absent
   unit retains the existing legacy-content fallback. Negative line/book
   locators are rejected. No shared API was added or changed.
