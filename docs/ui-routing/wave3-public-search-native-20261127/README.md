## Evidence failure boundary

The observer keeps exactly one immutable public request/execution for the process. Capture occurs before any fallible serialization or write. Checkpoint failure cannot discard the actual typed return; envelope failure retains both return and completed checkpoint reference. Publication is consumed before callbacks and never retries/rearms. Duplicate, nested and mismatched diagnostic captures refuse. The retained slot holds value metadata only, with no UI owner or executable closure.

The test requires the real App Intent's successful completion as well as the observer's real ACK; a later service failure cannot be masked by an earlier diagnostic ACK. URL cases additionally reject the original link error alert. Reporting failures remain explicit failures, with the actual return retained. The hook does not turn diagnostic evidence into a production success condition.

The observer serializes after the private Composition caller obtains its real execution but before the Host service's final qualification. Its DEBUG I/O therefore occupies part of the remaining original deadline; it does not extend that deadline. A deadline failure remains failure even if a diagnostic checkpoint contains an earlier actual ACK. Root accepted this instrumentation boundary; it is not a Release timing measurement.
