## Behavior

A request captures the actual selected profile/group documents, source owners, original window and backend before the first await. The original adapter performs its existing asynchronous preparation before Core. The same consumed Core preparation then selects the original Viewer root once, waits for its original mode publication and original UIKit parent witness, and consumes its existing one-use terminal capability. Only then does the complete original synchronous group terminal execute: snapshot flush, source validation, Store publication, source validation, native publication, and original pending-backend clear.

The new finite continuation is `workspaceSelection(profileID:workspaceID:activeTabID:)`. It must match `native.workspace.selection`, its exact retained profile/group and current-tab presentation. A nil active tab is offered only when the actual prepared documents and staged Readers are empty and the actual reservation has no selected tab. The unchanged ReaderTab branch still requires a nonnil tab and `native.reader.tab`.

The Viewer owner is checked again after the original flush and after the Store checkpoint. Those callbacks can change the original visible host without changing its root values. The Group owner therefore rereads the same host identity, original window and visible presentation while its phase is selecting or selected. This read-only check grants nothing.

The parent is never the final Group receipt. Loaded groups still require the original Reader/TextKit surface; empty iPad groups require the original empty Reader marker and empty phone groups require the original Library marker. The Session proposal preserves the final source/scene/request checks and existing canonical five-second budget.
